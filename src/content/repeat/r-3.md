# Where things live: files, paths and frontmatter

## The repo map

Every Claude Code mechanism in the exam guide, in one tree. **Shared** = committed to version control, so the whole team gets it.

```
~/                                    PERSONAL (never shared via VCS)
├── .claude.json                      MCP servers, user scope (personal / experimental)
└── .claude/
    ├── CLAUDE.md                     your instructions, every project, every session
    ├── commands/<name>.md            your personal /name commands
    └── skills/<name>/SKILL.md        your personal skills

my-project/                           SHARED (committed)
├── CLAUDE.md                         project instructions (or .claude/CLAUDE.md)
├── .mcp.json                         MCP servers for the team; secrets as ${VAR}
├── .claude/
│   ├── CLAUDE.md                     same role as root CLAUDE.md
│   ├── rules/*.md                    topic files; with paths: → only for matching files
│   ├── commands/<name>.md            team /name commands
│   └── skills/<name>/SKILL.md        team skills
└── src/payments/CLAUDE.md            directory-level: only when working in src/payments/
```

Three placement questions decide most config answers:
1. **Who needs it?** Everyone → project file. Only me → `~/`.
2. **When should it load?** Always / only for some files / only when asked.
3. **Must it *always* hold?** Then no file in this tree is enough. You need a hook or a permission rule (next chunks).

> **Exam trap:** "Tell every teammate to copy the rule into their `~/.claude/CLAUDE.md`" treats a scope problem as a communication problem. Move the rule to a file that is already shared.

## Frontmatter and syntax: the complete short list

The exam guide names very few keys. If an option uses a key that isn't here, suspect a distractor.

**`.claude/rules/*.md`**

```yaml
---
paths: ["**/*.test.tsx", "**/*.test.ts"]
---
Tests use describe/it blocks and data factories.
```

- `paths:` is a YAML list of globs. `**` = any number of folders, so the rule follows the *file type*, wherever it lives.
- **No `paths:`** → the file loads always, just like CLAUDE.md.

**`SKILL.md`**

```yaml
---
context: fork
allowed-tools: ["Read", "Grep", "Glob"]
argument-hint: "Path to the directory to analyze"
---
```

| Key | Effect |
|---|---|
| `context: fork` | Runs in an isolated sub-agent; only the final result comes back to the main session |
| `allowed-tools` | Limits which tools the skill may use while it runs |
| `argument-hint` | Prompts for the parameter when the skill is called without one |

**Imports inside CLAUDE.md:** `@standards/testing.md` — `@` directly before the path. Inside backticks it stays literal text. `import(standards/testing.md)` is not a thing.

**Personal version of a team skill:** a copy in `~/.claude/skills/` **with a different name** (e.g. `review-strict`). There is no `override: true` key.

> **Note (current docs):** `allowed-tools` now *pre-approves* tools (no permission prompt); removing tools is done with `disallowed-tools`. `argument-hint` is shown during autocomplete. Commands now accept the same frontmatter as skills. A personal skill with the *same* name overrides the project one, but only for you. The exam guide's descriptions above are what the exam tests.

## Loading triggers

Most config questions are really "*when* does this get into context?"

| Mechanism | Gets into context… |
|---|---|
| Project / user CLAUDE.md | At session start, every session |
| `@import`ed file | Together with the file that imports it, so also always |
| `.claude/rules/x.md` **without** `paths:` | Always |
| `.claude/rules/x.md` **with** `paths:` | Only when Claude works on a file matching a glob |
| Subdirectory CLAUDE.md | When working with files in that directory |
| Command / skill | Only when invoked |
| Hook | Not context at all: it's code that runs at its lifecycle point, every time |

Consequences worth remembering:
- Several rules can match the same file. **All** matching rules load. There is no priority between rule files.
- Splitting CLAUDE.md into `.claude/rules/` files does **not** by itself make them conditional. Only `paths:` does.
- A directory CLAUDE.md can't reach files outside its folder. For "all test files, everywhere", use `paths:`.
- An instruction seems ignored? Run **`/memory`** first to see which files actually loaded, before you rewrite the wording.

> **Note (current docs):** `/memory` lists and opens memory files; to see exactly which CLAUDE.md and rules files are loaded in the current session, current docs point to `/context`. Skill *descriptions* are always in context, and Claude can load a skill by itself unless `disable-model-invocation: true` is set. On the exam, `/memory` is the answer.

## Context vs enforcement, and MCP scope

Everything Claude *reads* is a request. Only code *enforces*.

| Context: probabilistic | Enforcement: deterministic |
|---|---|
| CLAUDE.md (all levels), `.claude/rules/`, commands, skills, system prompt, few-shot examples | Hooks (`PreToolUse`, `PostToolUse`), settings permission rules (`allow` / `deny` / `ask`), programmatic prerequisite gates |

Rule of thumb: "always, for everyone" → project CLAUDE.md. "Only for files like X" → rules + `paths:`. "Only when I ask" → command or skill. "Must hold no matter what the model decides" → hook or deny rule.

**MCP servers**

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
```

- `.mcp.json` in the project root = team servers, committed. `${GITHUB_TOKEN}` is filled from each developer's environment, so the secret is never committed.
- `~/.claude.json` = your personal or experimental servers.
- Tools from **all** connected servers are available at the same time, next to the built-in tools.
- Standard integration (GitHub, Jira, Slack)? Use the community server. Write your own only for team-specific workflows.
- **Resources** expose a catalog (docs tree, schemas, issue list) so the agent can see what exists without spending tool calls on guessing.

> **Note (current docs):** there is also a **local** scope (the default for `claude mcp add`). It is private to you, stored per project inside `~/.claude.json`. Env expansion also supports `${VAR:-default}`. The exam guide only contrasts `.mcp.json` (project) with `~/.claude.json` (user).
